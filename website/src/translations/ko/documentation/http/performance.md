# 성능

Deepkit은 각 라우트의 라우팅, 파라미터 파싱, 유효성 검사 및 직렬화를 JavaScript 함수로 컴파일합니다. 추가 리스너나 미들웨어가 없는 요청은 이 함수들을 차례로 직접 실행합니다.

## 요청의 비용

요청은 다음 단계를 거칩니다:

1. 라우트 매칭 (모든 라우트에 대해 하나의 컴파일된 함수)
2. path, query, headers 및 body의 파라미터 파싱과 유효성 검사 (라우트별로 컴파일됨)
3. 요청의 의존성 주입 스코프에서 컨트롤러를 생성하고 액션 호출
4. 반환 타입에 따라 결과를 직렬화하고 (라우트별로 컴파일됨) 응답 작성

컨트롤러까지의 상태에 리스너가 등록되어 있지 않은 한([이벤트](./events.md) 참조), 이 단계들은 직접 실행됩니다. 리스너(예: `httpWorkflow.onAuth`의 인증 리스너)나 미들웨어가 있으면 요청은 대신 이벤트 워크플로를 거치며, 이때 상태마다 이벤트 객체가 생성됩니다. 오류, 찾을 수 없는 라우트, 그리고 `onResponse`의 리스너(예: HTTP 액세스 로그)는 실제로 발생할 때만 워크플로로 넘겨지므로, 성공한 요청은 직접 경로에 머무릅니다.

## 벤치마크

벤치마크 머신(Intel Core i9-8950HK, 12 스레드, Linux, Node.js 26.13, Bun 1.4.4, Deno 2.9.6)에서 측정: 요청당 서버 프로세스의 CPU 시간(낮을수록 좋음), 같은 머신에서 [autocannon](https://github.com/mcollina/autocannon)으로 200개의 동시 연결, 세 라운드의 중앙값. 같은 머신의 부하 생성기가 서버보다 훨씬 먼저 한계에 도달하므로, 여기서는 초당 요청 수보다 CPU 시간이 더 의미 있습니다.

`GET /hello`는 `{hello: 'world'}`를 반환합니다. 두 POST 라우트는 중첩 객체, 배열, 날짜 및 숫자 범위를 포함한 JSON body를 검증하고(Hono는 zod, Deepkit은 TypeScript 타입) 작은 JSON으로 응답합니다: 1.8KB(GPS 포인트 10개를 가진 참가자 1명)와 357KB(각각 포인트 10개를 가진 참가자 200명). Node.js와 Bun은 네트워크에 대한 시스템 시간(모두 동일함)을 제외한, JavaScript 작업인 사용자 CPU 시간을 보여줍니다.

### Node.js

| | GET /hello | POST 1.8KB | POST 357KB |
|---|---|---|---|
| node:http (라우팅 없음, 유효성 검사 없음) | 17.4µs | – | – |
| Hono + @hono/node-server + zod | 22.5µs | 80.8µs | 5.63ms |
| **Deepkit** | **21.0µs** | **66.3µs** | **4.53ms** |

### Bun

| | GET /hello | POST 1.8KB | POST 357KB |
|---|---|---|---|
| 자체 라우터를 사용한 Bun.serve (유효성 검사 없음) | 5.9µs | 37.3µs | – |
| Hono + Bun.serve + zod | 8.5µs | 42.1µs | 4.15ms |
| `Bun.serve`와 `kernel.fetch`를 사용한 **Deepkit** | **9.7µs** | **41.6µs** | **2.38ms** |
| Bun의 `node:http`를 사용한 Deepkit | 15.4µs | – | – |

Bun은 `node:http` 호환 레이어보다 `Bun.serve`에서 훨씬 빠릅니다. `kernel.fetch`를 사용하세요. [서버 & 런타임](./runtimes.md#bun)을 참조하세요.

### Deno

`GET /hello`에 대한 요청당 사용자 및 시스템 CPU 시간: 라우팅 없는 `Deno.serve` 11.7µs, Hono 14.7µs, `kernel.fetch`를 사용한 Deepkit 18.9µs.

### 유효성 검사와 역직렬화만

HTTP 없이 동일한 데이터: 각각 날짜를 가진 2,000개의 GPS 포인트, 이미 JSON에서 파싱됨.

| | Node.js | Bun |
|---|---|---|
| zod `parse` (`z.coerce.date()` 사용) | 2.37ms | 2.30ms |
| Deepkit `cast` (역직렬화 및 유효성 검사) | 1.49ms | 1.14ms |
| zod `safeParse`, 날짜 대신 숫자 타임스탬프 | 1.38ms | 1.48ms |
| Deepkit validator, 숫자 타임스탬프 | 0.21ms | 0.14ms |
| 동일한 357KB의 `JSON.parse` | 2.24ms | 0.99ms |

날짜 변환이 없으면 유효성 검사 자체는 7배(Node.js)에서 10배(Bun) 빠릅니다. 날짜가 있는 경우, 2,000개의 `Date` 객체 생성이 그중 0.77ms를 차지하며, 이는 모든 라이브러리에서 동일합니다. 그리고 JSON 파싱은 유효성 검사와 비슷한 시간이 걸립니다.

## 팁

- **가능하면 동기 액션에서 일반 객체를 반환하세요.** 동기 액션은 요청마다 promise 없이 처리됩니다.
- **반환 타입을 명시하세요** (`hello(): { hello: string }`). 그러면 결과가 컴파일된 함수로 직렬화되며, 타입에 포함되지 않은 프로퍼티는 전송되지 않습니다.
- **미들웨어와 리스너는 필요한 라우트에만 사용하세요.** 컨트롤러까지의 상태에 있는 어떤 리스너든 모든 요청을 이벤트 워크플로로 옮기므로, `httpMiddleware.for(...).forControllers(...)`를 사용하거나 리스너에서 라우트를 확인하세요.
- **HTTP 액세스 로그**(`FrameworkModule` 옵션 `httpLog`)는 요청마다 한 줄을 포맷하고 기록합니다. 로드 밸런서나 프록시가 이미 요청을 로깅한다면 끄세요.
- 시작 시 **`kernel.warmUp()`을 호출하여** 첫 요청이 라우트를 컴파일하지 않도록 하세요. Cloudflare Workers에서는 필수입니다.
- **Bun과 Deno에서는** `node:http` 호환 레이어 대신 `Bun.serve`/`Deno.serve`와 함께 **`kernel.fetch`를 사용하세요**.

## 서버리스와 콜드 스타트

앱 생성(모듈, 의존성 주입 컨테이너, 라우터)에는 몇 밀리초가 걸리며, `warmUp()`을 사용하면 모든 라우트의 컴파일도 포함됩니다. 벤치마크 머신의 Node.js에서 Deepkit을 import하고 2,000개 GPS 포인트의 첫 페이로드를 검증하는 데 87ms(zod: 93ms), 이를 포함한 첫 100개 페이로드에 459ms(zod: 607ms)가 걸렸습니다. Bun에서는 61ms와 296ms(zod: 47ms와 436ms)였습니다. 첫 사용 시의 컴파일 비용은 몇 번의 호출 후에 회수됩니다.

시작 시간이 중요한지는 하나의 인스턴스가 처리하는 요청 수에 달려 있습니다: Lambda, Cloud Run 및 유사한 플랫폼은 여러 요청에 인스턴스를 재사용하므로, 시작 비용은 요청마다가 아니라 인스턴스당 한 번 지불됩니다. 요청마다 인스턴스를 시작하는 플랫폼에서는 어떤 프레임워크든 시작 시간이 모든 요청에 반영됩니다.
