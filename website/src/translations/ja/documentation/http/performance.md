# パフォーマンス

Deepkit は、各ルートのルーティング、パラメータの解析、バリデーション、シリアライゼーションを JavaScript 関数にコンパイルします。追加のリスナーやミドルウェアがないリクエストでは、これらの関数が順番に直接実行されます。

## リクエストのコスト

リクエストは以下のステップを経ます。

1. ルートマッチング（全ルートに対して 1 つのコンパイル済み関数）
2. パス、クエリ、ヘッダー、ボディのパラメータ解析とバリデーション（ルートごとにコンパイル）
3. リクエストの依存性注入スコープ内でのコントローラーの生成とアクションの呼び出し
4. 戻り値の型に従った結果のシリアライズ（ルートごとにコンパイル）とレスポンスの書き込み

コントローラーまでの状態にリスナーが登録されていない限り（[イベント](./events.md)を参照）、これらのステップは直接実行されます。リスナー（例: `httpWorkflow.onAuth` の認証リスナー）やミドルウェアがあると、リクエストは代わりにイベントワークフローを経由し、状態ごとにイベントオブジェクトが生成されます。エラー、見つからないルート、`onResponse` のリスナー（HTTP アクセスログなど）は、それらが発生した時にのみワークフローに引き渡されるため、成功したリクエストは直接パスのままです。

## ベンチマーク

ベンチマークマシン（Intel Core i9-8950HK、12 スレッド、Linux、Node.js 26.13、Bun 1.4.4、Deno 2.9.6）での測定値です。同一マシン上の [autocannon](https://github.com/mcollina/autocannon) から 200 の同時接続を行い、リクエストあたりのサーバープロセスの CPU 時間（低いほど良い）を 3 回の中央値で示しています。同一マシン上の負荷生成ツールがサーバーよりもはるかに先にボトルネックになるため、ここでは秒間リクエスト数よりも CPU 時間の方が意味があります。

`GET /hello` は `{hello: 'world'}` を返します。2 つの POST ルートは、ネストされたオブジェクト、配列、日付、数値範囲を含む JSON ボディをバリデーションし（Hono では zod、Deepkit では TypeScript の型）、小さな JSON で応答します。サイズは 1.8KB（10 個の GPS ポイントを持つ参加者 1 名）と 357KB（それぞれ 10 ポイントを持つ参加者 200 名）です。Node.js と Bun ではユーザー CPU 時間、つまり JavaScript の処理時間を示しており、全てで共通するネットワークのシステム時間は含んでいません。

### Node.js

| | GET /hello | POST 1.8KB | POST 357KB |
|---|---|---|---|
| node:http（ルーティングなし、バリデーションなし） | 17.4µs | – | – |
| Hono + @hono/node-server + zod | 22.5µs | 80.8µs | 5.63ms |
| **Deepkit** | **21.0µs** | **66.3µs** | **4.53ms** |

### Bun

| | GET /hello | POST 1.8KB | POST 357KB |
|---|---|---|---|
| 独自ルーター付き Bun.serve（バリデーションなし） | 5.9µs | 37.3µs | – |
| Hono + Bun.serve + zod | 8.5µs | 42.1µs | 4.15ms |
| `Bun.serve` と `kernel.fetch` を使用した **Deepkit** | **9.7µs** | **41.6µs** | **2.38ms** |
| Bun の `node:http` を使用した Deepkit | 15.4µs | – | – |

Bun は、`node:http` 互換レイヤーよりも `Bun.serve` の方がはるかに高速です。`kernel.fetch` を使用してください。[サーバーとランタイム](./runtimes.md#bun)を参照してください。

### Deno

`GET /hello` のリクエストあたりのユーザーおよびシステム CPU 時間: ルーティングなしの `Deno.serve` が 11.7µs、Hono が 14.7µs、`kernel.fetch` を使用した Deepkit が 18.9µs。

### バリデーションとデシリアライゼーションのみ

HTTP を介さない同じデータ: それぞれ日付を持つ 2,000 個の GPS ポイントで、JSON からはすでに解析済みです。

| | Node.js | Bun |
|---|---|---|
| zod `parse`（`z.coerce.date()` 使用） | 2.37ms | 2.30ms |
| Deepkit `cast`（デシリアライズとバリデーション） | 1.49ms | 1.14ms |
| zod `safeParse`、日付の代わりに数値タイムスタンプ | 1.38ms | 1.48ms |
| Deepkit バリデーター、数値タイムスタンプ | 0.21ms | 0.14ms |
| 同じ 357KB の `JSON.parse` | 2.24ms | 0.99ms |

日付変換なしの場合、バリデーション自体は 7 倍（Node.js）から 10 倍（Bun）高速です。日付ありの場合、2,000 個の `Date` オブジェクトの生成にそのうち 0.77ms かかり、これはどのライブラリでも同じです。また、JSON の解析にはバリデーションとほぼ同じ時間がかかります。

## ヒント

- **可能な限り、同期アクションからプレーンなオブジェクトを返してください。** 同期アクションは、リクエストごとに Promise を生成せずに処理されます。
- **戻り値の型を注釈してください**（`hello(): { hello: string }`）。これにより結果はコンパイル済み関数でシリアライズされ、型に含まれないプロパティは送信されません。
- **ミドルウェアとリスナーは、それを必要とするルートにのみ使用してください。** コントローラーまでの状態に対するリスナーが 1 つでもあると、全てのリクエストがイベントワークフローに移行するため、`httpMiddleware.for(...).forControllers(...)` を使用するか、リスナー内でルートを確認してください。
- **HTTP アクセスログ**（`FrameworkModule` のオプション `httpLog`）は、リクエストごとに 1 行をフォーマットして書き込みます。ロードバランサーやプロキシがすでにリクエストをログに記録している場合はオフにしてください。
- 起動時に **`kernel.warmUp()` を呼び出してください**。これにより最初のリクエストでルートがコンパイルされることはありません。Cloudflare Workers では必須です。
- **Bun と Deno では**、`node:http` 互換レイヤーの代わりに、`Bun.serve`/`Deno.serve` と共に **`kernel.fetch` を使用してください**。

## サーバーレスとコールドスタート

アプリの生成（モジュール、依存性注入コンテナ、ルーター）には数ミリ秒かかります。`warmUp()` を使用する場合は全ルートのコンパイルも含まれます。ベンチマークマシンの Node.js では、Deepkit のインポートと 2,000 個の GPS ポイントの最初のペイロードのバリデーションに 87ms（zod: 93ms）、それを含む最初の 100 ペイロードに 459ms（zod: 607ms）かかりました。Bun では 61ms と 296ms（zod: 47ms と 436ms）です。初回使用時のコンパイルは、数回の呼び出しで元が取れます。

起動時間が重要かどうかは、1 つのインスタンスが処理するリクエスト数によって異なります。Lambda、Cloud Run などのプラットフォームは 1 つのインスタンスを多数のリクエストで再利用するため、起動コストはリクエストごとではなくインスタンスごとに 1 回だけ発生します。リクエストごとにインスタンスを起動するプラットフォームでは、どのフレームワークでも起動時間が全てのリクエストに影響します。
